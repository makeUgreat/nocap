# 테스트 파싱

## 테스트 항목 생성
- nocap은 테스트 태그가 붙은 테스트 호출마다 테스트 항목 1개를 만듦 <!-- nocap: TP-001 -->
- nocap은 테스트 태그에 쓴 ID를 모두 쓴 순서대로 테스트 항목의 ID로 씀 <!-- nocap: TP-002 -->
- nocap은 테스트 태그에 같은 ID를 여러 번 쓰면 처음 한 번만 테스트 항목의 ID로 씀. 예: `// nocap: A-001, A-002, A-001`의 ID는 `A-001`, `A-002`임 <!-- nocap: TP-020 -->
- nocap은 테스트 태그가 없는 테스트 호출로 테스트 항목을 만들지 않음 <!-- nocap: TP-003 -->

## 테스트 호출 인식
- nocap은 `it`, `test`, `describe`, `suite` 호출만 테스트 호출로 인식함 <!-- nocap: TP-004 -->
- nocap은 수식자가 붙은 호출도 테스트 호출로 인식함. 예: `it.skip()`, `test.each([...])()`, `describe.only()` <!-- nocap: TP-005 -->
- nocap은 테스트 태그 바로 아래 줄에서 시작하는 호출 중 가장 바깥 호출 하나만 테스트 호출로 봄. 예: `describe('a', () => { it('b', () => {}) })`는 `describe`만 테스트 항목이 됨. `wrap(it('a', () => {}))`는 테스트 항목이 되지 않음 <!-- nocap: TP-026 -->

## 테스트 태그 인식
- nocap은 본문이 `nocap:`으로 시작하는 라인 주석만 테스트 태그로 인식함. 예: `// TODO`, `// @ts-expect-error`, `// @A-001`, `// NOCAP: A-001`, `// nocap : A-001`은 테스트 태그가 아님 <!-- nocap: TP-021 -->
- nocap은 테스트 호출 바로 위 줄의 라인 주석만 테스트 태그로 인식함. 빈 줄이나 다른 주석이 사이에 있으면 인식하지 않음 <!-- nocap: TP-006 -->
- nocap은 블록 주석과 코드 뒤에 붙은 라인 주석을 테스트 태그로 인식하지 않음. 예: `/* nocap: A-001 */`, `it() // nocap: A-001`, `foo() // nocap: A-001` <!-- nocap: TP-007 -->
- nocap은 콜론 뒤와 쉼표 앞뒤의 공백과 무관하게 같은 테스트 태그로 인식함. 예: `// nocap:A-001,A-002`와 `// nocap: A-001, A-002` <!-- nocap: TP-008 -->
- nocap은 마지막 ID 뒤의 쉼표와 무관하게 같은 테스트 태그로 인식함. 예: `// nocap: A-001, A-002`와 `// nocap: A-001, A-002,` <!-- nocap: TP-022 -->
- nocap은 문자열과 템플릿 리터럴 안의 `// nocap: ID`를 무시함 <!-- nocap: TP-010 -->

## 테스트 항목 정보
- nocap은 테스트 파일 경로와 테스트 호출이 시작하는 줄을 테스트 항목의 위치로 씀. 줄은 1부터 셈 <!-- nocap: TP-014 -->

## 틀린 태그
- nocap은 ID 하나라도 영문 대소문자, 숫자, `-`, `_` 밖의 문자가 있으면 그 테스트 태그로 테스트 항목을 만들지 않음. 예: `// nocap: A-001, A.1`, `// nocap: A-001 A-002` <!-- nocap: TP-018 -->
- nocap은 ID가 누락된 테스트 태그로 테스트 항목을 만들지 않음. 예: `// nocap:`, `// nocap: A-001,,A-002` <!-- nocap: TP-023 -->
- nocap은 틀린 테스트 태그의 위치와 틀린 이유를 보고함 <!-- nocap: TP-019 -->
- nocap은 테스트 파일 경로와 테스트 태그가 있는 줄을 틀린 테스트 태그의 위치로 씀. 예: 테스트 호출이 5줄에서 시작하면 위치의 줄은 4임 <!-- nocap: TP-025 -->
- nocap은 틀린 테스트 태그 1개에 틀린 이유를 1개만 보고함. ID 누락을 ID 규칙 위반보다 앞서 보고함. 예: `// nocap: A.1,,B`는 ID 누락 <!-- nocap: TP-024 -->

## 입력 언어와 오류
- nocap은 파일 확장자로 언어를 정함. `.ts`, `.mts`, `.cts`는 TypeScript, `.tsx`는 TSX, `.js`, `.mjs`, `.cjs`는 JavaScript, `.jsx`는 JSX로 읽음 <!-- nocap: TP-011 -->
- nocap은 지원하지 않는 확장자의 파일을 오류로 보고함 <!-- nocap: TP-012 -->
- nocap은 문법 오류가 있는 테스트 파일을 오류로 보고하고 그 파일로 테스트 항목을 만들지 않음 <!-- nocap: TP-013 -->
