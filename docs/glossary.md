# 용어집

- 이 문서는 도메인 객체가 쓰는 용어만 정의한다.
- 도메인 객체를 만들 때 같은 커밋에서 그 용어를 추가한다.

## spec

- 명세 문서(`SpecDocument`): 명세 항목을 담은 Markdown 파일이다. 명세 항목과 틀린 태그의 목록을 가진다.
- 명세 항목(`SpecItem`): 명세 문서에서 명세 태그로 ID를 받은 리스트 항목이다.
  - 명세 태그의 형식과 위치는 [nocap 문법](syntax.md)이 정한다.
- ID(`SpecId`): 명세 항목을 가리키는 값이다. 명세 태그의 `nocap:` 뒤에 쓴 값이다. 예: `<!-- nocap: AUTH-001 -->`의 ID는 `AUTH-001`
  - 테스트 태그는 이 ID로 명세 항목을 가리킨다.
  - 영문 대소문자, 숫자, `-`, `_`로만 쓴다. 대소문자를 구분한다.
- ID 후보: 태그 본문에서 `nocap:` 뒤의 값이다. 앞뒤 공백을 지운 값이다. ID 규칙은 아직 검사하지 않았다. 예: ` nocap: A.1 `의 ID 후보는 `A.1`
  - ID(`SpecId`)와 다르다. ID는 ID 후보 중 ID 규칙을 통과한 값이다.
- 태그(`Tag`): 주석 본문 중 `nocap:`으로 시작하고, `nocap:` 뒤의 값이 ID 규칙을 통과한 것이다. ID 1개를 가진다. 예: ` nocap: A-001 `의 ID는 `A-001`
  - 명세 태그와 테스트 태그는 같은 태그 어휘를 쓴다. 태그 형식과 태그 위치는 따로 정한다. 층 구분은 [nocap 문법](syntax.md#문법의-층)이 정한다.
- 명세 태그: 명세 문서의 HTML 주석 중 본문이 `nocap:`으로 시작하는 것이다. 예: `<!-- nocap: AUTH-001 -->`의 본문 ` nocap: AUTH-001 `
  - 명세 항목의 ID는 명세 태그에서만 온다.
- 명세 문장(`text`): 명세 항목이 된 리스트 항목의 첫 문단에서 명세 태그를 뺀 부분이다. 예: `- 계정을 잠금 <!-- nocap: AUTH-001 -->`의 명세 문장은 `계정을 잠금`
  - 명세 문장은 한 줄이다.
- 명세 주석(`SpecComment`): 명세 문서의 HTML 주석이다. 주석과 배치를 가진다. 코드 안의 주석은 포함하지 않는다.
  - 명세 문서의 형식을 읽는 쪽이 만든다. 주석 본문은 아직 검사하지 않았다. 예: `<!-- TODO -->`도 명세 주석이다.
- 배치(`SpecCommentPlacement`): 명세 주석이 Markdown 트리에서 놓인 곳이다. 찾는 순서는 [nocap 문법](syntax.md#꼬리-태그)의 트리 탐색이 정한다.
  - 첫 문단 끝(`first-paragraph-end`): 리스트 항목 첫 문단의 마지막 노드다. 리스트 항목이 시작하는 줄과 명세 문장을 가진다. 이 배치의 명세 태그만 명세 항목을 만든다.
  - 첫 블록 전체(`first-block`): 주석이 리스트 항목의 첫 블록 전체다. 명세 태그이면 명세 문장 없음(`no-sentence`) 틀린 태그가 된다.
  - 리스트 항목 안의 다른 곳(`elsewhere-in-item`): 명세 태그이면 리스트 항목 끝이 아님(`not-at-item-end`) 틀린 태그가 된다.
  - 리스트 항목 밖(`outside-item`): 명세 태그이면 리스트 항목 밖(`outside-list-item`) 틀린 태그가 된다.
- 틀린 태그(`InvalidTag`): `nocap:`이 있지만 명세 태그나 테스트 태그가 되지 못한 주석이다. 태그의 위치와 틀린 이유를 가진다.
  - 틀린 태그로는 명세 항목을 만들지 않는다. 틀린 테스트 태그는 테스트 항목에 ID를 주지 않는다.
  - 틀린 이유는 1개만 가진다. 순서는 [nocap 문법](syntax.md#틀린-태그)이 정한다.
  - 틀린 이유는 [nocap 문법](syntax.md#문법의-층)의 층으로 나뉜다.
- 어휘 위반(`VocabularyReason`): `nocap:` 뒤의 값이 1층 태그 어휘를 어긴 틀린 이유다.
  - ID 누락(`missing-id`): `nocap:` 뒤에 아무것도 없다. 예: `// nocap:`
  - ID 개수 초과(`multiple-ids`): `nocap:` 뒤에 ID가 2개 이상 있다. 그 값들을 가진다. 판정 기준은 [nocap 문법](syntax.md#틀린-태그)이 정한다. 예: `// nocap: AUTH-001, AUTH-002`
  - ID 규칙 위반(`id-rule-violation`): ID 후보가 ID 규칙을 어겼다. 그 ID 후보와 이유를 가진다. 이유는 처음 나온 틀린 문자로 정한다. 그 문자가 공백이면 이유는 공백(`invalid-whitespace`)이다. 다른 문자이면 이유는 틀린 문자(`invalid-char`)이고 그 문자를 가진다. 예: `// nocap: A.1/2`의 처음 나온 틀린 문자는 `.`
- 형식 위반(`FormReason`): 태그를 담은 주석이 2층 태그 형식을 어긴 틀린 이유다.
  - 블록 주석(`block-comment`): 블록 주석에 `nocap:`으로 시작하는 줄이 있다. 예: `/** nocap: AUTH-001 */`
- 위치 위반(`PositionReason`): 태그가 3층 태그 위치를 어긴 틀린 이유다.
  - 명세 문장 없음(`no-sentence`), 리스트 항목 끝이 아님(`not-at-item-end`), 리스트 항목 밖(`outside-list-item`): 명세 태그가 첫 문단 끝이 아닌 배치에 있다. 배치마다 어떤 이유가 되는지는 배치 항목이 정한다.
  - 코드 뒤의 주석(`after-code`), 테스트 호출 위가 아님(`not-above-test-call`): 테스트 태그가 어떤 주석 덩어리에도 들지 않았다.
  - 같은 ID 반복(`repeated-id`): 주석 덩어리 안에 같은 ID의 테스트 태그가 앞에 있다. 그 ID와 앞 태그의 줄을 가진다.

## test

- 테스트 파일(`TestFile`): 테스트 항목을 담은 파일이다. 테스트 항목과 틀린 태그의 목록을 가진다.
- 테스트 단위(`TestUnit`): 테스트 프레임워크가 실행하는 테스트 하나다. 시작하는 줄을 가진다. 시작하는 줄은 어노테이션과 데코레이터를 포함한다. 예: TypeScript의 `it()`, `describe()`
  - 무엇이 테스트 단위인지는 테스트 파일의 언어를 읽는 쪽이 정한다.
- 테스트 항목(`TestItem`): 주석 덩어리에 올바른 테스트 태그가 1개 이상 있는 테스트 단위다.
  - 테스트 태그의 형식과 위치는 [nocap 문법](syntax.md)이 정한다.
- ID 목록: 테스트 항목이 가리키는 명세 항목의 ID들이다. 주석 덩어리 안의 테스트 태그를 위에서 아래 순서로 따른다. 예: `// nocap: AUTH-002` 아래에 `// nocap: AUTH-001`이 있으면 ID 목록은 `AUTH-002`, `AUTH-001`
  - ID가 1개 이상 있다.
  - 같은 ID는 1번만 있다. 같은 ID의 뒤 태그는 같은 ID 반복(`repeated-id`) 틀린 태그가 된다.
- 테스트 태그: 테스트 파일의 라인 주석 중 본문이 `nocap:`으로 시작하는 것이다. 예: `// nocap: AUTH-001`의 본문 ` nocap: AUTH-001`
  - 테스트 항목의 ID 목록은 테스트 태그에서만 온다.
- 테스트 주석(`TestComment`): 테스트 파일의 주석이다. 주석, 끝 줄, 형태(`style`), 같은 줄의 코드 여부(`hasCodeOnLine`)를 가진다. 문자열 안의 주석은 포함하지 않는다.
  - 형태는 라인 주석(`line`)이나 블록 주석(`block`)이다. 라인 주석은 줄 끝까지 가는 주석이다. 예: `//`
  - 테스트 파일의 언어를 읽는 쪽이 만든다. 주석 본문은 아직 검사하지 않았다.
- 주석 덩어리(`CommentsAboveTestUnit`): 테스트 단위 바로 위에서 빈 줄 없이 이어진 테스트 주석들이다. 테스트 단위가 시작하는 줄과 테스트 주석 1개 이상을 가진다. 모으는 순서는 [nocap 문법](syntax.md#머리-태그)의 줄 탐색이 정한다.
  - 주석 본문은 보지 않는다. 예: `// TODO`도 주석 덩어리에 들어간다.
- 위치가 틀린 테스트 주석(`MisplacedTestComment`): 어떤 주석 덩어리에도 들지 않은 테스트 주석이다. 테스트 주석과 위치 이유를 가진다.
  - 위치 이유는 코드 뒤의 주석(`after-code`), 테스트 호출 위가 아님(`not-above-test-call`) 중 하나다.

## shared

- 주석(`SourceComment`): 읽는 쪽이 명세 문서나 테스트 파일에서 찾은 주석이다. 주석이 시작하는 줄과 본문을 가진다.
  - 본문은 주석 구분자를 뺀 원문이다. 앞뒤 공백을 지우지 않는다.
  - 태그(`Tag`)와 다르다. 태그는 주석 본문 중 `nocap:`으로 시작하고 ID 규칙을 통과한 것이다.
- 위치(`Location`): 명세 항목, 테스트 항목, 틀린 태그가 있는 파일 경로와 줄이다. 줄은 1부터 센다.
  - 명세 항목의 줄은 리스트 항목이 시작하는 줄이다. 테스트 항목의 줄은 테스트 단위가 시작하는 줄이다.
  - 틀린 태그의 줄은 태그가 시작하는 줄이다.

## coverage

- 커버리지(`Coverage`): 명세 항목과 테스트 항목을 ID로 연결한 판정 결과다. 커버리지 문제 목록과 명세 판정 목록을 가진다. 명세 항목 수와 커버된 명세 항목 수는 명세 판정 목록에서 센다.
  - 커버리지 비율과 다르다. 커버리지는 비율 값을 가지지 않는다.
  - 커버된 명세 항목은 ID가 다른 명세 항목과 겹치지 않고, 그 ID를 가리키는 테스트 항목이 1개 이상인 명세 항목이다.
- 명세 판정(`SpecJudgment`): 명세 항목 1개의 판정이다. 그 명세 항목을 가진다. 커버됨, 커버되지 않은 명세, 중복 ID 중 하나다.
  - 커버됨(`covered`): 그 ID를 가리키는 테스트 항목 1개 이상을 가진다.
  - 커버되지 않은 명세(`uncovered-spec`), 중복 ID(`duplicate-id`): 뜻은 같은 이름의 커버리지 문제와 같다. 커버리지 문제는 문제마다 1개이고, 명세 판정은 명세 항목마다 1개다. 예: ID가 같은 명세 항목 2개는 중복 ID 커버리지 문제 1개와 중복 ID 명세 판정 2개가 된다.
  - 중복 ID 명세 판정은 그 ID를 가진 명세 항목 2개 이상도 가진다. 그 명세 항목 자신도 포함한다.
- 커버리지 문제(`CoverageProblem`): 명세 항목과 테스트 항목의 연결이 깨진 곳이다. 커버되지 않은 명세, 알 수 없는 ID, 중복 ID 중 하나다.
  - 커버되지 않은 명세(`uncovered-spec`): ID가 겹치지 않는 명세 항목인데, 그 ID를 가리키는 테스트 항목이 없다. 그 명세 항목을 가진다.
  - 알 수 없는 ID(`unknown-id`): 테스트 항목이 가리키지만 어떤 명세 항목의 ID와도 같지 않은 ID다. 그 ID와, 그 ID를 가리키는 테스트 항목 1개 이상을 가진다. 예: 명세 항목에 없는 `AUTH-999`를 가리키는 `// nocap: AUTH-999`
  - 중복 ID(`duplicate-id`): 명세 항목 2개 이상이 같이 가진 ID다. 그 ID와, 그 ID를 가진 명세 항목 2개 이상을 가진다. 그 명세 항목들은 커버 여부를 판정하지 않는다.
