# 용어집

- 이 문서는 도메인 객체가 쓰는 용어만 정의한다.
- 도메인 객체를 만들 때 같은 커밋에서 그 용어를 추가한다.

## spec

- 명세 문서(`SpecDocument`): 명세 항목을 담은 Markdown 파일이다. 명세 항목과 틀린 태그의 목록을 가진다.
- 명세 항목(`SpecItem`): 명세 문서에서 명세 태그로 ID를 받은 리스트 항목이다.
  - 명세 태그의 형식과 위치는 [nocap 문법](syntax.md)이 정한다.
- ID(`SpecId`): 명세 항목을 가리키는 값이다. 명세 태그의 `nocap:` 뒤에 쓴 값이다. 예: `<!-- nocap: AUTH-001 -->`의 ID는 `AUTH-001`
  - 테스트 태그는 이 ID로 명세 항목을 가리킨다.
  - 영문 대소문자, 숫자, `-`, `_`로만 쓴다.
- 태그(`Tag`): 주석 본문 중 `nocap:`으로 시작하고, ID 후보가 모두 ID 규칙을 통과한 것이다. ID들을 태그 본문에 쓴 순서대로 가진다. 예: ` nocap: A-002, A-001 `의 ID들은 `A-002`, `A-001`
  - 명세 태그와 테스트 태그는 같은 태그 문법을 쓴다. 차이는 태그로 만드는 항목의 규칙뿐이다.
  - ID가 1개 이상 있다. 같은 ID가 여러 번 있을 수 있다. ID 개수는 검사하지 않는다.
  - ID 목록(`ids`)과 다르다. ID 목록은 테스트 항목이 가리키는 ID들이고 중복을 없앤 값이다.
- 명세 태그: 명세 문서의 HTML 주석 중 본문이 `nocap:`으로 시작하고 ID 1개를 쓴 것이다. 예: `<!-- nocap: AUTH-001 -->`의 본문 ` nocap: AUTH-001 `
  - 명세 항목의 ID는 명세 태그에서만 온다.
- 명세 문장(`text`): 명세 항목이 된 리스트 항목의 첫 문단에서 명세 태그를 뺀 부분이다. 예: `- 계정을 잠금 <!-- nocap: AUTH-001 -->`의 명세 문장은 `계정을 잠금`
  - 명세 문장은 한 줄이다. 첫 문단에 주석만 있으면 빈 문자열이다.

## test

- 테스트 파일(`TestFile`): 테스트 항목을 담은 파일이다. 테스트 항목과 틀린 태그의 목록을 가진다.
- 테스트 항목(`TestItem`): 테스트 파일에서 테스트 태그가 붙은 테스트 호출이다. 예: `it()`, `describe()`
  - 테스트 태그의 형식과 위치는 [nocap 문법](syntax.md)이 정한다.
- ID 목록(`SpecIds`): 테스트 항목이 가리키는 명세 항목의 ID들이다. 테스트 태그에 쓴 순서를 따른다. 같은 ID는 처음 한 번만 가진다. 예: `// nocap: AUTH-001, AUTH-002, AUTH-001`의 ID 목록은 `AUTH-001`, `AUTH-002`
  - ID가 1개 이상 있다.
  - 같은 ID는 1번만 있다. 테스트 태그에 같은 ID를 여러 번 쓰면 처음 1번만 남는다.
- 테스트 태그: 테스트 파일의 라인 주석 중 본문이 `nocap:`으로 시작하고 ID를 쉼표로 이어 쓴 것이다. 예: `// nocap: AUTH-001, AUTH-002`의 본문 ` nocap: AUTH-001, AUTH-002`
  - 테스트 항목의 ID 목록은 테스트 태그에서만 온다.
- 테스트 이름(`TestName`): 테스트 호출의 첫 인자로 정한 이름이다.
  - 정적인 이름(`static`)은 소스만 보고 값을 아는 이름이다. 예: `it('잠근다')`의 `잠근다`
  - 동적인 이름(`dynamic`)은 실행해야 값을 아는 이름이다. 소스 원문을 가진다. 예: `` it(`${n}번`) ``의 `` `${n}번` ``

## shared

- 태그 자리(`TagSite`): 태그 위치에 주석이 있는 리스트 항목이나 테스트 호출이다. 대상이 시작하는 줄, 대상, 주석을 가진다. 주석은 시작하는 줄과 본문을 가진다.
  - 태그 위치는 [nocap 문법](syntax.md)이 정한다. 명세 문서에서는 리스트 항목 첫 문단의 맨 끝이다. 테스트 파일에서는 테스트 호출 바로 위 줄이다.
  - 대상은 리스트 항목이면 명세 문장이고, 테스트 호출이면 테스트 이름이다.
  - 명세 문서의 형식이나 테스트 파일의 언어를 읽는 쪽이 만든다. 주석 본문은 아직 검사하지 않았다. 예: `// TODO`도 태그 위치에 있으면 태그 자리를 만든다.
  - 주석 본문은 주석 구분자를 뺀 원문이다. 앞뒤 공백을 지우지 않는다.
  - 주석이 명세 태그이면 리스트 항목이 명세 항목이 된다. 주석이 테스트 태그이면 테스트 호출이 테스트 항목이 된다.
  - 태그(`Tag`)와 다르다. 태그는 주석 본문 중 `nocap:`으로 시작하고 ID 규칙을 통과한 것이다.
- ID 후보: 태그 본문에서 `nocap:` 뒤를 쉼표로 나눈 값 1개다. ID 규칙은 아직 검사하지 않았다. 예: ` nocap: AUTH-001, A.1 `의 ID 후보는 `AUTH-001`과 `A.1`
  - 비어 있지 않다. 쉼표가 없다. 앞뒤에 공백이 없다.
  - ID(`SpecId`)와 다르다. ID는 ID 후보 중 ID 규칙을 통과한 값이다.
- ID 후보 목록(`IdCandidates`): 태그 하나에서 나온 ID 후보들이다. 태그 본문에 쓴 순서를 따른다. ID 개수는 아직 검사하지 않았다.
  - ID 후보가 1개 이상 있다. 마지막 쉼표 뒤의 빈 값은 ID 후보로 세지 않는다.
  - 같은 ID 후보가 여러 번 있을 수 있다.
  - ID 목록(`ids`)과 다르다. ID 목록은 ID 규칙을 통과하고 중복을 없앤 값이다.
- 위치(`Location`): 명세 항목, 테스트 항목, 틀린 태그가 있는 파일 경로와 줄이다. 줄은 1부터 센다.
  - 명세 항목의 줄은 리스트 항목이 시작하는 줄이다. 테스트 항목의 줄은 테스트 호출이 시작하는 줄이다.
  - 틀린 태그의 줄은 태그가 시작하는 줄이다.
- 틀린 태그: 본문이 `nocap:`으로 시작하지만 규칙을 어긴 명세 태그나 테스트 태그다. 태그의 위치와 틀린 이유를 가진다.
  - 틀린 태그로는 명세 항목이나 테스트 항목을 만들지 않는다.
  - ID 규칙 위반(`id-rule-violation`): ID 규칙을 어긴 ID 후보가 있다. 규칙을 어긴 ID 후보와 그 이유를 가진다. 이유는 그 후보에서 처음 나온 틀린 문자로 정한다. 그 문자가 공백이면 이유는 공백(`invalid-whitespace`)이다. 다른 문자이면 이유는 틀린 문자(`invalid-char`)이고 그 문자를 가진다. 예: `// nocap: AUTH-001, A.1/2`의 규칙을 어긴 ID 후보는 `A.1/2`이고 처음 나온 틀린 문자는 `.`. `// nocap: AUTH-001 AUTH-002`의 이유는 공백이다
  - ID 누락(`missing-id`): `nocap:` 뒤에 ID가 없거나 쉼표 사이가 비었다. 예: `// nocap:`, `// nocap: AUTH-001,,AUTH-002`
  - 명세 태그의 ID 개수 초과(`multiple-ids`): 명세 태그에 ID가 2개 이상 있다. 그 ID들을 가진다. 명세 태그에만 생긴다. 예: `<!-- nocap: AUTH-001, AUTH-002 -->`
