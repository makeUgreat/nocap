# nocap 개요

> [!NOTE]
> 이 문서는 Rust 구현의 목표임. 아직 구현하지 않았음

## 목표
- nocap은 자연어 명세의 규칙이 테스트로 확인되는지 추적함
  - LLM은 확률적이고 토큰을 많이 씀. nocap은 규칙과 테스트의 연결을 결정적이고 값싸게 알려 줌
- nocap은 규칙마다 연결된 테스트가 있는지 보장함
  - 테스트는 실행해서 참과 거짓을 확인할 수 있는 증거임. 구현 코드에 붙인 태그는 주장일 뿐임
- nocap은 같은 파일에서 항상 같은 결과를 냄

## 결과를 읽는 쪽
- 사람과 LLM agent는 텍스트 진단을 읽음. 프로그램은 구조화된 결과를 읽음
  - agent는 컴파일러식 진단을 보고 바로 행동함. 같은 정보를 JSON보다 적은 토큰으로 전함
  - 두 형식은 같은 검사 결과에서 만듦. 형식마다 내용이 갈라지지 않음
- nocap은 규칙 하나나 파일 하나에 대한 질의에 답함
  - agent는 전체 결과 대신 필요한 위치만 읽음
- nocap은 로컬 CLI, CI, agent가 부르는 CLI, 에디터(LSP)에서 실행함

## 본체와 플러그인
- 본체는 규칙과 테스트의 연결만 판정함
- 연결에 필요한 어댑터는 본체에 둠. 예: 명세 형식, 테스트 언어
  - 본체만 설치해도 연결 검사가 끝까지 동작함
- 연결을 넘는 판정은 플러그인이 함. 예: 테스트가 규칙을 충분히 검사하는지, 테스트가 통과하는지
  - 플러그인은 검사 결과만 받음. 그래서 공개 계약이 작음

## 문법
- 문법은 명세 형식과 테스트 언어에 중립인 1벌임
  - 형식이나 언어를 더해도 사용자가 배울 문법은 바뀌지 않음
- 어댑터는 문법이 쓰는 사실만 줌. 예: 주석, 블록, 코드 줄, 테스트 단위
- 테스트 언어마다 전용 어댑터를 둠
  - 지원하는 모든 언어에서 "커버됨"의 뜻이 같음

## 비목표
- nocap은 테스트를 실행하지 않음
- 본체는 LLM을 부르지 않고, 명세나 테스트의 의미를 판정하지 않음
- nocap은 규칙을 구현 코드와 연결하지 않음
- nocap은 저장소 밖의 명세를 읽지 않음
  - 외부 문서는 커밋과 상관없이 바뀜. 같은 커밋인데도 결과가 달라짐
- nocap은 코드 커버리지(실행된 줄과 분기의 비율)를 재지 않음
- nocap은 명세 문장의 품질을 판정하지 않음. 예: 모호함, 모순
- nocap은 파일을 만들거나 고치지 않음. 예: 태그 자동 수정, 테스트 뼈대 생성
  - 읽기만 하는 도구는 CI와 agent 루프에서 저장소를 바꾸지 않음
- nocap은 ID를 자동으로 붙이지 않음
  - ID의 접두어와 번호는 사용자의 관례임
- nocap은 실행 사이에 상태를 저장하지 않음. 플러그인은 자기 상태를 가질 수 있음
  - 결과는 그 커밋의 파일만으로 정해짐
