# 테스트 파싱

## 테스트 항목 생성
- nocap은 테스트 태그가 붙은 테스트 호출마다 테스트 항목 1개를 만듦 <!-- nocap: TP-001 -->
- nocap은 주석 덩어리 안의 테스트 태그의 ID를 위에서 아래 순서로 테스트 항목의 ID로 씀. 예: `// nocap: A-002` 아래에 `// nocap: A-001`이 있으면 ID는 `A-002`, `A-001`임 <!-- nocap: TP-027 -->
- nocap은 테스트 태그가 없는 테스트 호출로 테스트 항목을 만들지 않음 <!-- nocap: TP-003 -->

## 테스트 호출 인식
- nocap은 `it`, `test`, `describe`, `suite` 호출만 테스트 호출로 인식함 <!-- nocap: TP-004 -->
- nocap은 수식자가 붙은 호출도 테스트 호출로 인식함. 예: `it.skip()`, `test.each([...])()`, `describe.only()` <!-- nocap: TP-005 -->
- nocap은 주석 덩어리 바로 아래 줄에서 시작하는 호출 중 가장 바깥 호출 하나만 테스트 호출로 봄. 예: `describe('a', () => { it('b', () => {}) })`는 `describe`만 테스트 항목이 됨. `wrap(it('a', () => {}))`는 테스트 항목이 되지 않음 <!-- nocap: TP-026 -->

## 테스트 태그 인식
- nocap은 본문이 `nocap:`으로 시작하는 라인 주석만 테스트 태그로 인식함. 예: `// TODO`, `// @ts-expect-error`, `// @A-001`, `// NOCAP: A-001`, `// nocap : A-001`은 테스트 태그가 아님 <!-- nocap: TP-021 -->
- nocap은 테스트 호출 바로 위에서 빈 줄 없이 이어진 주석 줄을 그 테스트 호출의 주석 덩어리로 봄. 주석 줄은 주석만 있는 줄임 <!-- nocap: TP-029 -->
- nocap은 주석 덩어리 안의 테스트 태그를 모두 그 테스트 호출에 붙임. 다른 라인 주석과 블록 주석은 건너뜀. 예: `// nocap: A-001`, `// @ts-expect-error`, `it()` 순서이면 `A-001`이 `it()`에 붙음 <!-- nocap: TP-030 -->
- nocap은 빈 줄 위의 테스트 태그를 그 아래 테스트 호출에 붙이지 않음 <!-- nocap: TP-031 -->
- nocap은 블록 주석과 코드 뒤에 붙은 라인 주석을 테스트 태그로 인식하지 않음. 예: `/* nocap: A-001 */`, `it() // nocap: A-001`, `foo() // nocap: A-001` <!-- nocap: TP-007 -->
- nocap은 주석 안쪽 앞뒤와 콜론 뒤의 공백과 무관하게 같은 테스트 태그로 인식함. 예: `//nocap:A-001`과 `// nocap: A-001` <!-- nocap: TP-032 -->
- nocap은 문자열과 템플릿 리터럴 안의 `// nocap: ID`를 무시함 <!-- nocap: TP-010 -->

## 테스트 항목 정보
- nocap은 테스트 파일 경로와 테스트 호출이 시작하는 줄을 테스트 항목의 위치로 씀. 줄은 1부터 셈 <!-- nocap: TP-014 -->

## 틀린 태그
- nocap은 ID에 영문 대소문자, 숫자, `-`, `_` 밖의 문자가 있는 테스트 태그를 테스트 호출에 붙이지 않음. 예: `// nocap: A.1`, `// nocap: A-001 A-002`, `// nocap: A-001,` <!-- nocap: TP-033 -->
- nocap은 주석 덩어리에 틀린 테스트 태그가 있어도 나머지 테스트 태그로 테스트 항목을 만듦. 덩어리의 테스트 태그가 모두 틀리면 테스트 항목을 만들지 않음. 예: `// nocap: A-001` 아래에 `// nocap: A.2`가 있으면 테스트 항목의 ID는 `A-001`임 <!-- nocap: TP-034 -->
- nocap은 ID가 누락된 테스트 태그를 테스트 호출에 붙이지 않음. 예: `// nocap:` <!-- nocap: TP-035 -->
- nocap은 ID가 2개 이상인 테스트 태그를 테스트 호출에 붙이지 않음. `nocap:` 뒤를 쉼표로 나눈 값 중 빈 값이 아닌 것이 2개 이상이면 ID가 2개 이상임. 예: `// nocap: A-001, A-002`, `// nocap: A-001,,A-002` <!-- nocap: TP-036 -->
- nocap은 `nocap:`으로 시작하는 줄이 있는 블록 주석을 보고함. 줄마다 앞의 `*`와 공백을 지우고 찾음. 예: `/* nocap: A-001 */`, `/** nocap: A-001 */`, 여러 줄 JSDoc 안의 ` * nocap: A-001` <!-- nocap: TP-037 -->
- nocap은 주석 덩어리 밖의 테스트 태그를 보고함. 예: 빈 줄 위의 태그, `wrap(it())` 위의 태그, 일반 코드 위의 태그, 파일 끝의 태그 <!-- nocap: TP-038 -->
- nocap은 코드 뒤에 붙은 `nocap:` 라인 주석을 보고함. 예: `foo() // nocap: A-001`, `it() // nocap: A-001` <!-- nocap: TP-039 -->
- nocap은 주석 덩어리 안에 같은 ID의 테스트 태그가 2개 이상이면 첫 태그만 테스트 호출에 붙이고 뒤의 태그를 보고함 <!-- nocap: TP-028 -->
- nocap은 틀린 테스트 태그의 위치와 틀린 이유를 보고함 <!-- nocap: TP-019 -->
- nocap은 테스트 파일 경로와 테스트 태그가 있는 줄을 틀린 테스트 태그의 위치로 씀. 예: 테스트 호출이 5줄에서 시작하면 위치의 줄은 4임. 여러 줄 블록 주석이면 `nocap:`으로 시작하는 줄을 씀 <!-- nocap: TP-025 -->
- nocap은 틀린 테스트 태그 1개에 틀린 이유를 1개만 보고함. 위치 위반, 블록 주석, ID 누락, ID 개수 초과, ID 규칙 위반, 같은 ID 반복 순서로 앞의 것을 보고함. 예: `foo() // nocap: A.1`은 위치 위반, `// nocap: A.1, B`는 ID 개수 초과 <!-- nocap: TP-040 -->

## 입력 언어와 오류
- nocap은 파일 확장자로 언어를 정함. `.ts`, `.mts`, `.cts`는 TypeScript, `.tsx`는 TSX, `.js`, `.mjs`, `.cjs`는 JavaScript, `.jsx`는 JSX로 읽음 <!-- nocap: TP-011 -->
- nocap은 지원하지 않는 확장자의 파일을 오류로 보고함 <!-- nocap: TP-012 -->
- nocap은 문법 오류가 있는 테스트 파일을 오류로 보고하고 그 파일로 테스트 항목을 만들지 않음 <!-- nocap: TP-013 -->
